# AGENTS.md — project guide for contributors (human or AI)

Goal: C++ source that Visual C++ 6.0 (cl 12.00.8168) compiles into the same bytes as the original `tsh.exe`, function by
function, written so a reader would accept it as the original author's source. Read `README.md` first, then
`docs/DECOMP_WORKFLOW.md` and `docs/RE_NOTES.md` (confirmed findings about the executable).

## Rules of the repo
- **No game files.** Never commit `tsh.exe`, extracted assets, Ghidra exports/projects, or data generated from the exe
  (`src/K_*.cpp` are generated by `tools/data/gen_data.py` and are git-ignored).
- **Match honestly.** A function counts as matched only when the compiled bytes are identical *and* the source reads like
  something the original authors would write. A fakematch is anything that exists only to coax the compiler: dummy
  variables with no meaning, `__asm`, `#pragma` tricks, hex-address casts instead of typed globals, `volatile` to fix
  registers, empty `if`/`do{}while(0)`. Keep such attempts in a `*_open.cpp` file with a `// OPEN:` note instead.
- **Original assembly** (e.g. `_alloca_probe`) is not source: list it as ORIGINAL-ASM.

## Compiler and dialect
- VC6 `cl /O2 /D WIN32 /D NDEBUG /D _WINDOWS` (see `tools/build_all.py`); per-file extra flags go in `config/flags.tsv`
  (`/GX` for files whose classes have exception frames: `E_app.cpp`, `H_list.cpp`, `M_app.cpp`).
- C++98 as VC6 accepts it (`for` variables leak into the enclosing scope, no `long long` literals without `i64`).
  `struct Game` methods are `__thiscall`; free functions are `__cdecl` unless the bytes show `ret N` (then `__stdcall`).

## Naming
- Placeholders keyed by address/offset stay until the meaning is certain: methods `M_xxxxxxxx`, free functions `FUN_xxxxxxxx`,
  globals `DAT_xxxxxxxx`, `Game`/`Slot` members `m_XXXX` (hex offset). The comparer maps these names back to addresses.
  Real names go in `config/symbols_*.tsv` as `mangled<TAB>address` once certain.
- Locals and parameters get meaningful names, never `iVar1`/`local_8`/`param_1`/`undefined4`. Use real types.
- Style: 4-space indent, braces on the line after function headers only, minimal comments (why, not what), no dead code.

## Layout
- `src/<P>_<topic>.cpp` — matched code, in address order within a file. The letter `P` is the work partition the code was
  written in during the first parallel campaign (A..M); it is only a file prefix. Unfinished or non-matching functions live in
  `<P>_open.cpp` with an `// OPEN:` note saying what differs.
- `config/` — `functions.tsv` (address, name, size, region), `game_fields_*.tsv` / `slot_fields_*.tsv` (members at offsets),
  `game_methods_*.txt` (declarations of `Game` methods; unlisted `M_xxxxxxxx` calls are auto-declared `void M_xxxxxxxx();`),
  `game_prelude_*.h` (types, externs, free functions), `symbols_*.tsv`, `flags.tsv`, `lanes/` (the original work lists).
  `include/game.h` is generated from these by `tools/gen_game_h.py` — never edit it. Always `grep` all files for a name or
  offset before declaring it; identical duplicates merge, conflicting ones print a WARNING.
- `tools/` — `build_all.py` (compile + compare + report), `compare_obj.py`, `compare_data.py`, `report.py`, `progress.py`,
  `asm.py`, `fn.sh`, `gap_table.py`, `tsh_words.py` (word-bank format), `data/` (data generator), `ghidra/` (export scripts),
  `perm/` (a small source-mutation permuter, see `docs/reports/M.md`).
- `docs/` — findings and the per-partition reports (what was tried on each open function, diagnosed wall classes).

## Build and check
```
set VC6_DIR=C:\Program Files (x86)\Microsoft Visual Studio      (the folder that contains VC98\)
pip install -r requirements.txt
python tools/build_all.py                          all code; writes build/progress.tsv, build/results.tsv
python tools/build_all.py --file A_game.cpp --verbose      one file, with side-by-side diffs
python tools/build_all.py --data --report build/report.json   also data, and an objdiff-format report
python tools/asm.py 00401120                        original disassembly of one function
```
The comparer masks only relocations to symbols it cannot resolve; a MATCH needs identical bytes and identical relocation
targets. Jump tables and trailing bytes are part of the function.

## Hard-won lessons
Model data first (typed globals, record structs, enums), then transcribe. `sub r,k; je; dec r; je` runs are `switch`
statements. A hoisted zero register usually means a differently scoped variable. `while (1) { ...; if (c) break; ... }`
compiles differently from `do {} while`, `for` and `while (c)`. `BOOL f = TRUE; if (x == 0) f = FALSE;` yields
`mov eax,1; jne; xor eax,eax`. Check loop bounds against relocation addends. Park a function after a handful of attempts.

## Working in parallel (git worktrees)
Several people or agents can work at once, each in a worktree of their own: `git worktree add build/wt/<L> -b lane-<L>` (build/ is
git-ignored), copy `orig/tsh.exe` into the worktree, then build there with `python tools/build_all.py --file <L>_foo.cpp`.
Lane lists are in `config/lanes/<L>.tsv`. To avoid merge conflicts a lane only **adds new files**: `src/<L>_*.cpp`,
`config/game_fields_<L>.tsv`, `config/slot_fields_<L>.tsv`, `config/game_methods_<L>.txt`, `config/game_prelude_<L>.h`,
`config/symbols_<L>.tsv` and `docs/reports/<L>.md`. A function fixed in a new file wins over its parked copy in an older
`*_open.cpp` (the report keeps the best result per address); delete the parked copy later in a separate cleanup commit.
Commit on the lane branch as you go; do not push. Keep scratch scripts under `build/`.
